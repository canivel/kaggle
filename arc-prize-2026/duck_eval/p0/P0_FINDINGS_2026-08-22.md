## P0.1 — RESET SEMANTICS. VERDICT: RESET returns to LEVEL start under the shipped config. P2 LIVES. [V-sim]

Driven end-to-end on the real engine: `ls20-9607627b` (real environment file, real
`arc_agi.Arcade` OFFLINE + `LocalEnvironmentWrapper`) taken to **level 1 by replaying 21 human
actions** (`data/human_replays/ls20_actions.json`), then probed. Script:
`scratchpad/p0_reset_semantics.py`; raw results: `duck_eval/p0/p0_reset_results.json`.

| Case | Config | Result [V-sim] |
|---|---|---|
| A | `ONLY_RESET_LEVELS=true`, RESET after 2 actions on level 1 | **level_reset**: level index 1 kept, score 1 kept, `full_reset=False`, returned frame **byte-equal to the recorded level-1 start frame** |
| D | flag true, RESET with `_action_count==0` (fresh level) | **level_reset**, frame byte-equal to level-1 start |
| B | flag UNSET, RESET with `_action_count==0` while on level 1 | **FULL reset**: snapped to level 0, score 0, `full_reset=True`, frame byte-equal to level-0 start — the footgun, reproduced |
| C | flag UNSET, RESET after 1 action on level 1 | level_reset (footgun only bites at `_action_count==0`) |

Also observed: the level-1 start frame is **deterministic across two independent clears** (byte-equal), so P2's "RESET re-anchors to a known frame" premise holds on this game. [V-sim]

Mechanism, from the installed wheel source [V-source] (`wheels/site/arcengine/base_game.py`):
- `handle_reset` L305-316: `ONLY_RESET_LEVELS=="true" and state != WIN` → `level_reset()`; elif `_action_count==0 or state==WIN` → `full_reset()`; else `level_reset()`.
- `set_level` L148-163 zeroes `_action_count` (L160) **on every level transition** — so without the flag, the first RESET on any freshly-entered level full-resets to level 0. This is the exact trap `taaf/game_api.py:215-222` documents.
- `level_reset` L326-329 clones only the current level from `_clean_levels`; `_score` and `_current_level_index` survive. `full_reset` L318-324 zeroes score and returns to level 0.
- `os.getenv` is read **per RESET call** (L311), not cached — the flag can be toggled mid-process (our Case B/C did exactly that).
- The flag is set process-wide by the shipped harness itself at `taaf/game_api.py:222` (after `arcade.make`, so the make-time RESET still full-resets), independent of `taaf_kaggle_run.ipynb:339`. Belt and braces. [V-source]
- None of the 25 real games overrides `handle_reset` / `full_reset` / `level_reset` (grep over all environment files) — base-class semantics apply everywhere. [V-source]
- Caveat: with the flag set, RESET after **WIN** still full-resets (L311 `state != WIN` guard). Irrelevant to P2 (no retry after a win) but worth knowing. [V-source]

**Gate outcome: P0.1 PASSES — P2 (reset-anchored episodic retry) may be built.**
