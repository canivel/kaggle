## 1. ToolFailBench: Diagnosing Tool-Use Failures in LLM Agents
- arXiv:2607.04686v1 (2026-07-06) — https://arxiv.org/html/2607.04686v1
- Takeaway: Taxonomy of 4 tool-use failure modes (Tool-Skip, Result-Ignore,
  Output-Fabrication, Unnecessary-Tool-Use). **Explicitly documents two open-weight models
  (glm-4-9b, mistral-7b) producing zero clean executed tool calls on tool-required tasks** —
  they emit "tool-style" prose ("Per <tool>,...") that is classified Tool-Skip because no
  executed call appears. Best model (Grok-4.3) only 86.3% clean tool-use.
- **Verdict: ADAPT.** This is the closest published analogue to our 72B format livelock and
  gives us named vocabulary ("Tool-Skip" = emits tool-style prose, never a native call) to
  cite in the A17 error model. It offers *diagnosis, not mitigation* (paper defers fixes),
  so it confirms our root-cause framing but does not resurrect the 72B route. Fold the
  Tool-Skip label into learnings/a17_error_model.md; no new build.

## 2. Decoupling Task-Solving and Output Formatting (Deco-G)
- arXiv:2510.03595v2 (updated 2026-07-10) — https://arxiv.org/html/2510.03595
- Takeaway: Delegates format compliance to a separate Format Estimation Module so the LLM
  "focuses solely on problem-solving." Related thread (NL-to-Format two-stage, CRANE
  interleaved free/grammar decoding) documents 10-30% task degradation from hard constrained
  decoding — i.e. forcing the format can hurt reasoning.
- **Verdict: IGNORE (for the 72B route), note the principle.** Deco-G assumes the model can
  already complete the task and only steers *how* it is formatted — it would not help a model
  that reasons but never emits a call, per the authors' own scoping. But the broader finding
  (forced/constrained decoding degrades reasoning) is corroborating evidence for why our v5
  forced-tool_choice boot "passed" yet the free-form run livelocked: the forcing was masking,
  not fixing. Confirms 72B-dead call; no action.

## 3. No Time Like the Present: Agentic Test-Time Training (aTTT)
- arXiv:2607.03441v1 (2026-07-03) — https://arxiv.org/html/2607.03441v1
- Takeaway: Updates LoRA adapters *during* episodes with token-level reweighting that
  downweights loss on tokens from repeated n-grams (explicitly targets the "repeated
  self-training loop" where an agent replays failed behavior). +5.0 ALFWorld, +4.9 SWE-bench
  Lite; 1.9x wall-clock overhead; requires gradient weight updates.
- **Verdict: IGNORE (now), watch.** Requires per-episode gradient/LoRA updates and ~2x
  compute — incompatible with our zero-cloud-budget, Kaggle-kernel-only, fixed 9h no-final-
  rerun window. The *idea* (penalize repeated-n-gram loops) is conceptually adjacent to our
  livelock, but weight-update TTT is off the table this campaign. Park.

## 4. AGI Maze: Benchmark Framework for World-Modeling Agents
- arXiv:2607.00627v1 (2026-07-01) — https://arxiv.org/abs/2607.00627v1
- Takeaway: Lightweight grid-maze benchmark, partially observable + stateful, needs internal
  world state. Finding: vanilla LLMs "fail to represent mazes internally at inference time,"
  and even with message-history working memory cannot solve small mazes within a
  human-trivial step budget.
- **Verdict: IGNORE (adopt as reading, not as a dep).** Reinforces our latent-state-audit
  concern (why EWM+banking is blocked): message-history-as-memory does not give reliable
  hidden-state modeling on grid tasks. No ARC-AGI-3 tie, no harness to adopt. Useful as a
  citation for the "LLMs lack usable world state" prior; no build.
