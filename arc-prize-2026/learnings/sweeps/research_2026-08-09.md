## 3. New items

### Field: agentic harness design / programmatic substrate — **3 new, 1 decision-relevant**

- **2608.06370 — "The Bitter Lesson of Tool Calling" (08-06).** Programmatic tool calling (PTC: tools as
  **typed Python stubs** the model invokes through code, execution + results in a **single agent turn**) vs
  native JSON tool calling on BFCL v4 across 14 models. PTC matched or exceeded JSON in **11/14**; GPT-5.6
  family **+10.6%**; under a "schema flood" ablation (128 schemas incl. cross-domain decoys) **JSON degrades
  −2.3% while PTC *improves* +5.5%**; **13/14 under parallel operations**. The 3 losses (GPT-4o 81.9→55.0,
  GPT-4.1 81.9→62.1, GPT-5.4-mini 79.3→55.0) are a **formatting capability gap**: those models emit literal
  `\n` character sequences instead of real newlines, producing subprocess syntax errors. Inference-only.
  Provenance: **preprint**, closed-model eval, no open weights.
  **ADOPT (design + pre-mortem) — lane (a), arm P1/S2.** Reasons and the one caution, both load-bearing:
  1. This is the **first multi-model evidence that the duck's existing shape is the right shape**. The duck
     already exposes **exactly one tool** `{"name":"python","parameters":{"code":…}}` and already passes
     `step_env` into the sandbox (§3(a) of the proposal). PTC is that shape, and it wins.
  2. **It does NOT discharge the weak-model objection.** Zero open-weight models (no Qwen, no Llama, no
     parameter counts published). Proposal §3(a) evidence-against (i) — "no weak-model ablation exists in any
     of the three" — **stands unamended**. Do not let this paper be quoted at panel as covering our 27B.
  3. **[V-2nd, HTML read, verify before quoting]** the same ablation reports a **filesystem-based reference
     condition degrading 32% on average**. If that holds on a direct read, it is a genuine discriminator
     *inside* lane (a): an **in-process persistent namespace** (our P1) beats a **workspace-filesystem
     artifact store** (Tycho's `world_model.py` + `notes/`). That is an argument for the sequencing the
     proposal already chose, arrived at independently.
  **Cheapest test under our constraints ($0, 0 pushes, workstation-only):** transcript forensics on existing
  `runs/kernel_pulls/war_eval_v1/` — measure the 27B's rate of **malformed code emissions**, specifically
  literal-`\n`-instead-of-newline and subprocess syntax errors, in the existing `python` tool calls. This is
  the *identified* failure mode of PTC and it is measurable **before** spending the S2 push. Pair it with the
  already-planned 2608.04828 skill-trigger pre-mortem (§5.4) — same transcript pass, one job.

- **2608.05144 — Argus: A General-Purpose Agentic Runtime for Long-Horizon Reasoning (08-05).**
  Manager/Planner/Engineer/Reviewer over **persistent project state**; weights **fixed**, self-evolution lives
  in "persistent runtime state and control policy". ~78% SWE-Bench Pro (vs 59% Direct Copilot), AARRI-Bench

  **ADAPT (design only) — lane (a).** Independent support that *persistence of state, with frozen weights*, is

  co-primary. No build: multi-role orchestration collides with the P8 sub-agent exclusion (GPU contention).

### Field: memory / context management for long-horizon agents — **1 new, upgrades lane (b)**

- **2608.05906 — MERIT: Causal Episodic Memory for Feedback-Driven Agent Repair (08-06).**
  **Training-free.** Online **dual-polarity** memory: oracle-verified **corrections** *and* observed
  **unsuccessful directions**. Spider 66.34 → **69.79**; BIRD 47.35 → **48.44**; runs on
  **Qwen2.5-7B-Instruct**; beats Reflexion-style memory (51.24 BIRD) at lower compute. Preprint; code not stated.
  **ADAPT — lane (b), arm P3.** This is the item that changes a stated fact in the proposal:
  §3(b) says *"FocusMem's memory is **trained** → free-Kaggle-GPU-build item at best, not an inference-time
  patch."* **MERIT is the inference-time shape**, and it is demonstrated on a **7B open model** — the only
  weak-model memory datum in three sweeps. It also gives external support to the disposition in §5.1: storing
  **"observed unsuccessful directions"** *is* the refuted-hypothesis list, kept as a P3 canary rather than a
  standalone arm — MERIT says that content belongs **in the memory store**, not in a digest injected into the
  window (which is the A22 design that died).
  **Two honest discounts.** (i) Effects are small (+3.45pp / +1.09pp) and the domain is text-to-SQL, not
  interactive games. (ii) It requires an **oracle** to verify corrections; mid-game on ARC-AGI-3 we have no
  oracle — though the **next frame is a cheap falsifier**, which is exactly the Tycho `transition`-match
  channel the proposal already adopts. That connection is the design note, not a claim.
  **Cheapest test:** none new. Fold into the already-sequenced **S4/P3 un-wipe** as the store's *schema*
  (two polarities, entries carry the verifying observation). $0 until S4.

### Field: experience banking / replay / skill libraries — **cluster, net NEGATIVE for skill-store designs**

- **2608.05810 — When Self-Evolution Backfires: Pre-Commit Gating against Skill Contamination (08-06).**
  Self-evolving agents are **non-monotonic**: past a critical pool size, new skills **degrade** performance —
  a capability-contamination **phase transition**. Mechanism: a flawed skill becomes reference material for
  the next skill, creating **cross-round contamination chains**. **Post-hoc removal recovers only a small part
  of the drop — the damage is largely irreversible.** Fix = **Verifier-as-Gatekeeper**, three heterogeneous
  critics (structural validity, behavioural harmlessness, semantic consistency) gating admission, plus
  marginal-gain subset selection. **72% pass@1 Terminal-Bench 2 with a pool ~5× smaller**; the **frozen** pool
  **transfers positively to four other backbones and a second benchmark without re-evolution**. No training.
  Preprint. **ADAPT (risk control) — gates any future skill-store lane, NOT S1b.**
  Two things for the panel: (1) "accumulate skills and things get better" is now published as **false**, and
  the harm is **irreversible** — that is a strong argument for keeping (c) as the *narrow deterministic replay*
  it currently is and refusing scope creep into a skill store; (2) the **frozen-pool cross-backbone transfer**
  is the first datum in three sweeps that speaks to our **generalisation rail** in a favourable direction.
- **2608.06196 — Comparative Approaches to Agent Retrieval over Large Skill Libraries (08-06).**
  Hybrid lexical+dense ranker: 73.5% hit@5 over a 690-skill corpus, 117 queries. A **typed knowledge graph**
  encoding prerequisites/data-flow/ordering **made it worse by −11.2pp (p = 0.0007)**: 98.6% of typed edges
  connect skills the ranker already co-surfaced, and ~73% of missed queries are unreachable through the graph
  (**pre-filter topology bound**). Separately: **author-written query benchmarks overstate performance by up
  to 44pp**. Preprint. **ADAPT (methodology) — applies to us directly.**
  The 44pp self-authored-benchmark inflation is the **same disease as our standing de-rating rule**, now with
  a measured magnitude. Worth adding to the R24 §5.3(2) ruling as a numeric anchor. The typed-graph negative
  is a cheap "don't build that" for any P3 store: **flat typed entries + a good ranker beat a relational
  graph**.
- **2608.05573 — SkillTV-Bench: How Well Judges Perform on Skill-Augmented Agentic Execution (08-06).**
  681 cases / 50 tasks / 11 domains. Verification by **inspecting artifacts and environments directly**,
  explicitly **not by replay**. A reusable externalised `JudgeSkill` (+14.8pp accuracy, refined by an evolution
  loop on misjudged cases → not fully training-free). Offline selection lifts trajectory success **22.9%
  (1 rollout) → 45.5% (10 rollouts)**. Preprint. **MONITOR.**
  Relevant to "verification-by-replay" as a **counterpoint**: the strongest published verifier design in this
  batch deliberately rejects replay in favour of artifact inspection — consistent with lane (a)'s falsifier
  (check the artifact against observation) rather than lane (c)'s (re-execute the trace).
- **2608.05604 SkillZip** (contract-preserving skill-graph compression to 100K skills), **2608.05245
  Search2Skill** (RL-distilled skills), **2608.04562** (Shapley valuation of skills), **2608.04482** (cluster-
  contrastive capability pages), **2608.06137 SkillTFM** (tabular), **2608.05139** (skill entropy, training),
  **2608.05204 SkillTrace** (provenance auditing), **2608.05563** (trajectory poisoning, 91% ASR),

## 5. Final verdict — does anything change R24?

**Lane ranking: NO CHANGE. (a) > (c) > (b) stands, and (a) is marginally stronger than it was yesterday.**

1. **Lane (a) gains its first substrate evidence and one internal discriminator.** 2608.06370 is the first
   multi-model comparison saying the *programmatic-Python-tool* substrate beats the alternative, and — the
   part that matters — that it **gets better, not worse, as context degrades** (+5.5% vs JSON's −2.3% under
   schema flood). That is the opposite sign to everything A22 measured, and it is the cleanest published
   statement of the eviction-after-externalisation reconciliation in §2.2. The `[V-2nd]` filesystem −32%
   result, if it survives a direct read, says the **in-process namespace (P1) should be preferred to a
   workspace-file artifact store** — an argument for the exact thing S2 already tests.
2. **The weak-model hole is NOT closed and the panel must be told so.** Every new item today is frontier-model
   (Argus/GPT-5.5, Bitter Lesson/closed Anthropic+OpenAI only) with **one** exception — MERIT on
   Qwen2.5-7B — and that exception is in lane (b), text-to-SQL, with a +3.45pp effect. Proposal §3(a)
   evidence-against (i) survives intact. The K4 canary (`namespace_reuse_rate ≥ 0.15`) remains the right
   instrument precisely because the literature still cannot answer this for us.
3. **Two factual amendments the proposal needs before sealing.**
   - **§3(c): withdraw "Field 3 is near-empty across two consecutive sweeps — one enabling paper, no field
     behind it."** False (§2 above). Replace with: *the field is dense but is about cross-task skill libraries,
     not within-game trace replay; its principal finding (2608.05810) is that naive skill accumulation is
     non-monotonic and irreversibly harmful past a pool-size threshold, which argues for keeping (c) narrow
     and deterministic.* The down-ranking of (c) survives on the **public-set / generalisation-rail** objection,
     which is untouched by anything today.
   - **§3(b): "FocusMem's memory is trained → free-Kaggle-GPU-build item at best"** is now too strong. MERIT
     (2608.05906) is the training-free, weak-model shape. (b) stays a **component arm (P3)**, not a lane —
     but the reason changes from *infeasible without training* to *feasible, thin evidence, small effects,
     needs an oracle we only have via the next-frame falsifier*.
4. **Sequence S1 → S1b → S2: UNCHANGED.** Nothing found argues for reordering, and both free falsifiers remain
   correctly placed ahead of the one push. **One addition, $0 and zero pushes:** fold a
   **code-well-formedness pre-mortem** into the already-planned §5.4 transcript-forensics pass — measure the
   27B's rate of literal-`\n`-instead-of-newline and subprocess syntax errors in existing `python` tool calls
   on `runs/kernel_pulls/war_eval_v1/`. This is the *documented* failure mode that sank PTC for 3 of 14
   models, it is the cheapest possible way to de-risk S2, and it costs one extra pass over transcripts we are
   already reading for the 2608.04828 skill-trigger check.
5. **§5.2 (A22 formal death record) can be sealed as written** — third consecutive sweep with zero
   compaction-theory activity and zero rebuttals to 2608.01326.
6. **§5.3(2) (de-rating rule): add a numeric anchor.** 2608.06196 measures self-authored query benchmarks
   overstating performance **by up to 44pp**. That converts the de-rating rule from a stance into a
   quantified prior, and it is a peer-independent source.
