## Summary (2 sentences)

v4 shows genuinely improved process discipline — the §Semantics code forensics, the abolition of 1-seed screens, and the exploratory/confirmatory split are the right instincts — but the measurement system it now rests on is internally incoherent (two dispersion estimates differing 5–7× drive opposite decisions), the "confirmed" scoring model's live validation is circular, and the R1b confirmatory design lets an unmeasured nuisance cell (wall discount) decide the outcome. Separately, the plan's own P-weighted arithmetic caps at ~1.16 against a 1.35–1.5 top-100 cutoff and a 1.61 leader, and contains zero levers that improve agent capability rather than scoring plumbing.

## Objections

**[MAJOR] The two variance estimates are mutually inconsistent by ~5×, and H4 plus the phase1-v2 closure both rest on the unreconciled one.** The control pool {0.82, 0.89, 0.93, 1.02, 0.95} has sd ≈ 0.074, implying a 1-seed paired-Δ sd of ≈ 0.074·√2 ≈ 0.105 on the Kaggle rail — yet the bootstrap reports 0.52 and H4 uses that number to abolish 1-seed screens. These cannot both describe the same population; my best guess is the 0.52 is a *per-game* delta sd (consistent with tail games like ft09 +3.0) while screens are judged on ~19-game aggregates, a unit error of √19. This is decision-relevant, not pedantic: under sd 0.105, phase1-v2's +0.19 Kaggle mean is ~1.8σ and "noise per H4, line CLOSED" is wrong; under sd 0.52 the control σ̂ is a 5× underestimate and every gate threshold in the plan is miscalibrated. State exactly what population the 20k bootstrap resamples (per-game vs per-submission aggregate; which rail), reconcile with the observed control dispersion, and re-adjudicate phase1-v2 and the H4 seed minimums under the corrected number.

**[MAJOR] The §Semantics "live confirmation" is circular, and the claim that LB validation is impossible is overstated — a discriminating aggregate probe is feasible.** The 4-decimal agreement is between the wheel formula and taaf `final_score`, both computed by the same shipped codebase; it confirms you can read the code you already read, not that the LB server implements it. But hypothesis discrimination does not require per-game artifacts: the pooled-tax model and the v3 max-across model make *different quantitative predictions for the aggregate LB score* of a purpose-built probe (e.g., a build that deliberately fires one post-clear RESET per game with a known action count — pooled semantics predicts a computable first-clear tax; max-across predicts near-zero cost). One or two scored windows convert "identity is assumed" into a falsifiable test of the single assumption the entire v4 plan is built on. Recording "the panel should stop requesting it" is premature; request withdrawn only if a probe design provably cannot separate the hypotheses in aggregate.

**[MAJOR] R1b's confirmatory outcome is decided by an unvalidated nuisance cell, and two of its inputs are double-dipped from exploratory data.** (a) The exploratory Δ crosses the +0.10 kill line within the stated discount range (+0.22 at disc 1.0 → +0.037 at 0.365), so the wall-cost cell alone determines pass/fail — yet it will be measured from *null* histories, whose per-action wall profile need not match a restart-heavy policy (restarts change when and how walls are hit; you already possess sched-v1 traces to measure this directly, excluded from the control pool but valid as wall-cost data). (b) The park-FP cell is fixed at 10.1%/−0.068 measured from the same 2026-07-13 exploratory corpus the confirmatory replay will run on — that is data reuse; report the denominator (how many stuck-at-90 runs?) and propagate a CI, or re-measure on fresh runs. (c) With a 5-seed holdout and gains dominated by rare deep recoveries (ft09 contributes +3.0 alone), pre-register the false-kill and false-pass rates of the Δ < +0.10 threshold via bootstrap before running, or the "confirmatory" label is decorative.

**[MAJOR] The portfolio contains no capability lever, and by the plan's own arithmetic it cannot close the gap it names.** P-weighted contributions sum to ≈ +0.08 to +0.24 over base 0.922 → ceiling ≈ 1.16, versus a top-100 cutoff of 1.35–1.5 and leader 1.61. All three legs (fork ports, restart scheduling, L2 wall shot) optimize scoring mechanics; none improves the agent's ability to solve games — no world-model induction, no action-effect learning, no level-structure inference — on a benchmark whose leader gap almost certainly reflects capability, not plumbing. Either (i) add at least one pre-registered capability hypothesis with a mechanism for >+0.3, or (ii) state explicitly that the Nov-2 objective is not rank-competitive and what it is instead; "the build is for Nov-2" is currently an unfalsifiable deferral with no lever attached to it.

**[MAJOR] Port-bundle attribution rides on an instrument the plan itself declared unreliable, and the acceptance criterion is unspecified.** LA-N6's disposition attaches "per-delta local ablation evidence" for attribution, but the same document exhibits a 3-seed sign flip between pod and Kaggle rails (+0.169 vs −0.73) and demotes pod runs to non-binding — so per-graft attribution is generated on a rail with unknown (possibly non-positive) correlation to deployment. Additionally, "joint non-inferiority on actions/level + tokens/action" has no stated margins, so the gate is not falsifiable as written. Fix: pre-register the non-inferiority margins numerically; run a small cross-rail calibration (same config, k ≥ 4 paired 2-seed runs across rails) to estimate the rail correlation before trusting any pod-derived attribution or screen.

**[MINOR] §Semantics should be an executable, version-pinned specification, not prose with line numbers.** The confirmed model cites `api.py:417`, `scorecard.py:192/430/655`, etc., against an unpinned wheel; a Tufa wheel bump between now and Nov 2 silently invalidates every corollary. Encode the invariants (one-run-per-game_id, action pooling, first-clear tax, WIN-gated replay path) as pytest assertions run against the installed wheel hash in CI, with a loud failure on version change. This is cheap, in-repo, and converts the plan's single most load-bearing assumption into something that falsifies itself.

## Questions for the authors

1. What exactly does the 20k null-vs-null bootstrap resample — per-game deltas or full-submission aggregates — and on which rail? Reconcile sd 0.52 with the control pool's observed sd 0.074, and state which number H4 and the phase1-v2 closure should have used.
2. How many stuck-at-90 runs underlie the 10.1% park-FP estimate, and what is its confidence interval? Will R1b propagate that uncertainty or treat it as a constant?
3. What single wall-discount value (or measured distribution) will R1b commit to before running, and what are the pre-computed false-kill/false-pass rates of the Δ < +0.10 threshold under it?
4. Can you design a ≤2-window LB probe whose *aggregate* score discriminates pooled-tax from max-across semantics? If you claim no, show the calculation that the two hypotheses' aggregate predictions are indistinguishable at LB noise levels.

7. Is there any candidate lever, however speculative, with a mechanism for >+0.3 — and if not, what is the falsifiable definition of success for Nov 2?
