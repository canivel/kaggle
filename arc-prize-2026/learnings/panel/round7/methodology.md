**New objections:**

**[MAJOR] NEW-1: The best-across EV column silently drops the FP loss, inconsistently with the table's own budget model — the +0.24 headline is likely double-counted and the lever may be dead under *both* scoring semantics.** Arithmetic: in every row, net-best-across = gain + FP recovery with FP loss zeroed (90,2: 0.185+0.059=0.244≈0.243). But the gain column is computed with disc(t) = value in the first N−t actions, i.e., it assumes a **shared per-game action budget** — and under a shared budget, truncating an FP run at t=90 destroys its post-90 clear regardless of whether the scorecard takes last-attempt or best-across (best-across cannot resurrect a truncated attempt). "FP restarts cost nothing" is only valid if attempts carry **independent** budgets, in which case disc(90)=0.365 is the wrong discount for the fresh attempt (it would get a full budget) — so the table is internally inconsistent under either budget model. If shared-budget is correct, best-across net at (90,2) ≈ 0.185−0.242+0.059 ≈ 0.00 and the entire R1 conditional leg collapses, fact-check moot. Fix: state the budget model explicitly, recompute both columns under one consistent model, and add "best-across + shared budget" as a third branch of the fact-check.

**[MAJOR] NEW-2: The Track B error rate "P(≥3 events all-spurious) < 0.01" is not a null probability — it is 0.101³, which answers no well-posed hypothesis test.** The 10.1% is a per-*restarted-stuck-run* counterfactual attribution rate. If the null against which the gate screens produces lookalike events at anything near that rate, then with ~13.8 restarted stuck runs/draw the null event count across 2 windows is ~Binomial(≈28, 0.101), mean ≈2.8, and P(≥3 | null) ≈ 0.5 — fifty times the advertised error rate, with a likelihood ratio near 1 against the predicted alternative of ≈3 events. If instead the intended null is "fresh attempts never clear" (context-carryover failure), the null event rate is ≈0, the 10.1% is irrelevant, and the test is vacuous as *validation* (it can only fail to fire). Fix: define the null precisely, publish the simulated event-count distributions from the replay engine under (a) exchangeability holds and (b) exchangeability fails, set the threshold at the null's 95th percentile, and print the honest power — which will force either more windows or a redesigned statistic (e.g., restrict events to games with per-game null clear rate 0/10, where attribution is clean).

**[MAJOR] NEW-3: The scoring-semantics fact-check — the single branch point deciding the R1 leg — has no pre-registered protocol or decision rule.** "A one-day binary fact-check" is not an experiment description. Required: a *behavioral* probe (an engineered attempt sequence — clear, then deliberately worse attempt — submitted to a public scorecard, reading whether the score reflects best or last), not documentation reading; a pre-registered decision rule including the disagreement case (docs vs. behavior); and, per NEW-1, a third outcome branch for shared-budget/best-across. A binary gate on an unspecified measurement is exactly the single-noisy-observation failure mode this panel exists to catch.
