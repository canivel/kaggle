## Summary (2 sentences)
This brief reports a null first draw (0.91, z≈−0.16) for a heavily-instrumented harness ("warpack") whose two headline mechanisms — banking (in-run max-over-plays trace replay) and resubmission order statistics — are both, by the authors' own admission, unobservable in the very data they generate, and then proposes to immediately stack a second unobservable intervention (ledger+escalation A/B) on top tonight. The strategic math is the real problem: the mechanism they call "working as designed" (R1 fast-submit + order stats) cannot arithmetically close the 0.42 gap to the 1.44 wall, so the entire plan is load-bearing on R2–R5 interventions for which this document presents zero efficacy evidence.

## Objections

**[MAJOR] Q1(a) violates the authors' own blocking logic — sequencing incoherence.** Q3 declares variance reconciliation (ME-NEW-11) *blocking* because "it decides whether 3-seed gates have any power," yet Q1 proposes flipping ledger+escalation ON *tonight*, i.e., committing scored window 1 of the R2 A/B before that reconciliation exists. If the true Δ-sd is 0.52 rather than ~0.10, a "≥3 window" A/B has essentially no power to detect a +0.10–0.15 effect and window 1 is a wasted scored draw with added regression risk. Actionable fix: make R2 launch *conditional* on the variance reconciliation completing today, and publish the implied minimum-detectable-effect for the chosen window count before the flag flips. If reconciliation isn't done by the 19:00 hard stop, tonight's arm must be (b), not (a).

**[MAJOR] Ledger+escalation is the designated "leveler" with zero efficacy evidence and no visible mechanism description — smoke tests are not screens.** The only evidence offered is "smoke-tested 48/48 incl. banking verbatim-replay on real engines," which establishes the code runs, not that it scores. Your own constraint sheet says "screens ≥3 seeds where scored" — show the ≥3-seed *local efficacy screen* for ledger+escalation, with per-game deltas, or explain why R2 is exempt from your own gate. The pre-registered predictions P1–P5 live in an external file; for the panel to approve burning scored windows, the predicted effect sizes must be inline (what lift, on which games, detectable at what n?). As written, "R2–R5 is the leveler" is exactly the kind of it-will-work-when-we-turn-it-on assertion I reject in agent-scaffolding papers.

**[MAJOR] Banking's verbatim-replay carries an unvalidated determinism assumption in an unobservable execution environment.** Max-over-plays winning-trace replay only banks value if the game engine in the *hidden scored rerun* replays traces deterministically (same seeds, same state transitions, same timing behavior under the 11h20m soft_end). Your 48/48 smoke tests ran locally; you have explicitly zero per-game artifacts from any scored run, so a silent replay divergence (trace replays, fails, burns play budget) would be indistinguishable from noise at σ̂=0.074 — and worse than useless at sd=0.52. Actionable: emit an aggregate, non-per-game canary into the scored output (e.g., counts of replay-attempted / replay-succeeded folded into a checksum-style side channel in the submission-visible totals, or reconstructable via your proposed wheel-formula check) so replay integrity in the rerun is at least binarily observable.

**[MAJOR] The order-statistics mechanism cannot reach the wall — the gap math contradicts the strategy narrative.** With a control band of mean 0.922, σ̂ 0.074, the expected max over even 60 daily draws is ≈ mean + 2.3σ ≈ 1.09; the 1.44 wall is a ~7σ event under your own band. So "the wall mechanism (fast-submit + order stats) is now adopted" (Q4) is false as a gap-closing claim — order stats buy you ~+0.1 to ~1.05, full stop. This isn't pedantry: it means Q4's "no response needed" answer is only defensible if R2–R5 have combined EV ≥ +0.35, which nothing in this document supports (see objection 2). State explicitly, with numbers, how much of the 0.42 gap each track is budgeted to close.

**[MAJOR] The warpack arm has no valid control — the A/B baseline is a different build.** Q2 concedes the war kernel "is NOT the frozen fork" and that control-band accounting is unresolved, yet §1a already computed a z-score for warpack draw #1 against the frozen-fork control set {0.82…1.02}. If warpack itself shifts the mean (recovery, shortcircuit, soft_end all touch scoring-path behavior), then the R2 A/B — war-v2 vs war-v1 alternating across windows — starts with n=1 on the war-v1 side and a contaminated prior. Actionable: define the war-v1 band as its own arm requiring ≥3 draws before any war-v2 contrast is interpreted, and pre-register that number now.

**[MINOR] Fast-submit gate "live and validated" on n=1, with a fail-catastrophic failure mode.** The gate's RUN_HEAVY detection deciding between a 0.6s dummy write and the real run means a detection misfire in the hidden rerun scores ~0 for that day. One successful 0.91 rerun is existence proof, not validation of a load-bearing daily mechanism. Add a startup assertion path (fail loudly rather than write dummy in ambiguous environments) and log the detection signal into the scored artifact if any channel exists.

**[MINOR] sched-v1 draw #2 sits in the queue with no kill criterion.** Q1(c) flags it as "stale — superseded?" but defers the decision indefinitely; a queue item that will never be run is queue-hygiene debt and risks being auto-submitted by the daily mechanism. Kill it or re-justify it today.
