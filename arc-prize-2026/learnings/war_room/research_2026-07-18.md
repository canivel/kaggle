## ARC-AGI-3 direct — the big one

**OPINE-World: Programmatic World Modeling with Ontology-error-Prioritized Interactive
Exploration** ([arXiv:2607.01531](https://arxiv.org/abs/2607.01531), v1 Jul 1, **v2 Jul 15**;
Courtis, Li, Sanner) — LLM agent that learns an **object-centric programmatic world model
online** from interaction. Two cooperating agents in a hypothesis-and-test loop: one acts,
one **synthesizes the transition model as Python source** and refines it via
counterexample-guided inductive synthesis (CEGIS). Exploration is steered by a Bayesian
"ontology error" (object-type adequacy) signal. Assumes the transition function is a
**deterministic** function of state+action; uses a **replay check against the settled
state** to verify each hypothesized rule. Headline: **solves 20/25 ARC-AGI-3 public games
and 160/183 levels with NO per-game training**, action-efficiency 78.4 vs human; program
synthesis and neural latent world models solve *none* of the same set.
**Verdict: ADAPT (highest-priority read of the sweep).** This is the strongest published
ARC-AGI-3 result to date and it operationalizes three things our war-v3/N5 lines already
converged on independently: (a) **frame-determinism is a first-class modeling assumption**
(matches our banking replay constraint — all 25 games deterministic per N5), (b) the model
is an **executable rule bank** (matches the OCM-style "verified procedure bank" flagged
07-16), and (c) **replay verification of predicted vs settled state** is exactly the
PREDICT→RESULT ledger wiring in Q1(d). The full CEGIS/two-agent loop is heavier than our
zero-budget single-flag windows allow, but the *replay-check contract* ("hash the predicted
next frame, compare to actual settled frame, log mismatch as a no-effect/refutation FACT")
is a cheap, gate-testable extraction that gives the ledger a firing trigger. Directly feeds
Q1(c) fingerprint refutation + Q1(d) PREDICT→RESULT. Mine the v2 appendix for the ft09-class
games in its solved 20/25.

## Agentic harness / gate methodology — uncanny match to our own process

**Self-Evolving Agent Harnesses via Gated Semantic Quality-Diversity (GSME)**
([arXiv:2607.13683](https://arxiv.org/abs/2607.13683), **Jul 15**) — evolves a *frozen*
model's harness (prompts/control-loop/config, not weights) via a MAP-Elites archive keyed
by **diagnosed failure pathology (where × why), not task id**. Separated propose-and-credit
loop: a stronger LLM diagnoses failures and writes patches; **deterministic code owns all
measurement, significance testing (paired-2σ gates), and a withheld sealed test**. Three
sequential gates: validity (reruns infra failures), **activation (credits a patch ONLY when
its mechanism actually fired)**, significance (paired-2σ on held-out). +9 to +15.5pp sealed
gains across 6 domains, 86–147% train-retention.
**Verdict: ADOPT (methodology, immediately).** This is external, peer-style validation of the
*exact* discipline the campaign already runs — and it names the missing gate we lacked. Our
07-17 ledger screen failed because 1552 digests fired 0 escalations: that is precisely a
**failed activation gate** (mechanism never fired → no credit possible). GSME says: make the
activation check a *first-class pre-gate* so a war-v3 flag cannot even enter the significance
window until its trigger is demonstrably firing on the build rail. Adopt as a written
amendment to the war-v3 build protocol: **(1) activation gate BEFORE Δlc significance;
(2) archive war-v3 candidates by failure-pathology bucket (budget-death, verbatim-resubmit,
game-over-deadlock, stuck-loop) rather than by mechanism name** — this directly organizes
the Q1(a–g) backlog. Also validates keeping the LLM (diagnosis) and deterministic code
(measurement) strictly separated, which we already do.

## Benchmark power / task-count (governance)

**How Many Tasks Are Enough for Agent Benchmark Decisions? A Replay Analysis**
([arXiv:2607.12338](https://arxiv.org/abs/2607.12338), **Jul 14**) — replays completed
SWE-bench / AppWorld / tau-bench records to find the minimum task fraction for reliable A/B
decisions. Finding: **wildly benchmark-dependent** (AppWorld reliable at 15% of tasks,
tau-bench 25%, SWE-bench Verified needs 90%, SWE-bench Lite never converges even at 95%).
Recommends every partial-eval report pre-specify: required margin, task-selection method,
coverage, decision rule, and acceptable % of unresolved comparisons.
**Verdict: ADAPT (weak, governance only).** No mechanism for us, but it independently
vindicates the campaign's stance that our 25-game build rail is a *structure-specific* power
problem (07-14 variance reconciliation: build-rail sd 0.572 vs LB σ 0.074; gate MDE ≈ 0.14).
It argues against ever trusting a sub-full-panel look — which is exactly why the 07-17 gate
required all 25 pooled games × 3 seeds. Cite in the §3 methods record; no build action.

## Distillation (war-v4 / GPT-5.6 decomposition line)

**Privileged Information Distillation for LMs (π-Distill / OPSD)**
([arXiv:2602.04942](https://arxiv.org/abs/2602.04942)) — distills frontier *agents* when only
**action trajectories** are exposed (reasoning hidden): a PI-conditioned teacher + unconditioned
student trained jointly, or RL with reverse-KL to the PI teacher. **Verdict: IGNORE (for now).**
Feb paper (not new; surfaced as most-relevant to the GPT-5.6→Qwen decomposition question but
predates the window). Direction is right for war-v4 — if we ever bank GPT-5.6 winning traces
and want a 72B student to imitate them, "action-only PI distillation" is the correct framing —
but it requires a training loop we cannot run under the zero-budget rule. Park with war-v4;
revisit only if a train-side rail opens.

## Serving / war-v4 (72B AWQ, RTX PRO 6000 96GB)

No genuinely new arXiv result in the window. Web consensus reconfirms (not new): **AWQ INT4 is
the 2026 default for VRAM-constrained single-GPU serving**, vLLM/SGLang/TensorRT-LLM all ship
optimized AWQ kernels, 72B-AWQ fits comfortably in 96GB — **but INT4 is explicitly cautioned
against for reasoning/code/math-heavy work** (quality loss most visible there), which is
precisely the ARC grinder regime. **Verdict: IGNORE (no new evidence); note the caveat.** war-v4
should benchmark 72B-AWQ against the grinder set specifically, not assume INT4 parity on the
reasoning games. If quality regresses, FP8/W8A8 on the same 96GB rail is the fallback to test.
