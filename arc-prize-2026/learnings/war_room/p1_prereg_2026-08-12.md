## 0. The single question this arm answers

**Does refusing to spend actions the runner can prove carry no information —
plus handing the agent a small non-truncatable record of what it has already
tried — change behaviour, without harming levels-completed?**

This is a **bookkeeping repair**, not a strategy idea. The defect is measured in
our own artifacts: on the 17 cleared levels of `animation_v1`, **117 of 1,110
actions (10.5%) re-execute a `(board, action)` pair already executed on that
level**, and the root cause is in the transcripts — `context_budget_tokens:
31744` / 33 history messages on a level that ran 225 actions over 62 analysis
steps. The harness already exposes `history` / `transitions` / `last_transition`
as preloaded Python globals; **the agent never queries them.**

## 2. THE ARM — one flag, three mechanisms, shipped defaults

`P1_SUPPRESS=1` on the duck baseline. **NO** warpack, **NO** ledger graft, **NO**
sentinel, **NO** compaction, **NO** animation. The (f) continuation default
rides (07-23 amendment), so the comparator family is
`duck-harness-kaggle-continuation-v1`.

- **A — memo decline.** Per level, `(board_hash, action_key) -> outcome`. A pair
  is declined (not spent; the memoised outcome and a one-line note are returned)
  only when **all** of: the game is not flagged ambiguous; the pair has been
  executed **≥ 2** times with consistent outcomes (`P1_CONFIRM=2`); its confirmed
  outcome left the board **byte-identical** (`P1_MEMO_MODE=noop`); and it has not
  already been declined this level (`P1_MAX_DECLINES=1`).
- **B — batch abort.** The remainder of a multi-action batch is not executed once
  an action no-ops, or closes a loop **inside that same batch**
  (`P1_ABORT_CYCLE=1`). **`P1_ABORT_REVISIT=0` — OFF. See §4.**
- **C — non-truncatable memory block.** ≤ 900 characters appended to the user
  message every turn (the user message is rebuilt each turn, so trimming can
  never reach it): board fingerprint, distinct boards seen this level, untried
  primitives at this exact board, confirmed-dead primitives at this exact board,
  and an explicit "this game has latent state" line when the detector has fired.

**Explicitly NOT in this arm** (so it cannot be smuggled in later):
`P1_MEMO_MODE=all`, `P1_ABORT_REVISIT=1`, any change to the system prompt, any
change to batch-size policy (that is P2 and is a *separate* build), any
frontier/Go-Explore routing (P3).

## 3. ENDPOINTS

### M0 — PRIMARY: mechanism delivery (the only endpoint that may be read as evidence)

The family `duck-harness-kaggle-continuation-v1` has **m = 2** (lc 10, 16) and is
therefore **NOT SCREENABLE** under `SCREEN_PROTOCOL` §1 P2. Per §4.6, the primary
endpoint must be a mechanism endpoint, exactly as it was for the animation arm.

**M0 = `saved / requested`** where `saved = declined + aborted` and
`requested = saved + executed`, read from the single `P1 CANARY` line.

**Sealed expectation, from the offline replay of the three recorded runs:**

| run | replayed `saved/requested` |
|---|---|
| `animation_v1` | 306 / 5,151 = **5.9%** |
| `a22_v2_seed1` | 697 / 3,492 = **20.0%** |
| `a22_compaction_v1` | 841 / 4,777 = **17.6%** |

**Pre-registered band: `saved/requested` ∈ [3%, 30%].** Below 3% the mechanism
did not engage and the arm is a null by delivery; above 30% it is suppressing
far more than the recorded traces support and must be inspected before any
reading. *(Lesson from the animation kill: probe-derived rates do not survive
contact with a real agent. These are **replay-of-a-real-agent** rates, not
random-walk rates, which is the strongest basis available — but the band is
deliberately wide and asymmetric for exactly that reason.)*

### M1 — SECONDARY, DESCRIPTIVE ONLY: Δlc vs the family

`mean Δlc` per game vs the m = 2 family. **At m = 2 this is NOT screenable and
MAY NOT be reported as non-harm** (`SCREEN_PROTOCOL` §1 P2, §4.6). It is
reported descriptively with the sign test and nothing more. The advisory K3″
line at the pooled σ̂ = 0.14174 (df 6) and C(2) = 2.10 is **−0.2977**; it is
quoted as advisory arithmetic only.

### M2 — SECONDARY: RHAE score

Arm local-25 score vs the family, and the multiplier. **Sealed replay
expectation with the shipped defaults: ×1.040 / ×1.003 / ×1.015** (mean ×1.019,
i.e. local +0.065 / +0.004 / +0.022). This is the honest replay number for what
ships. **It is NOT the diagnosis's ×1.10** — see §4.

### M3 — SECONDARY: duplicate re-execution rate

`dup_exec / executed` from the canary. Replay expectation with the shipped
defaults: **6.9% / 3.4% / 4.1%** (as-run on cleared levels: 10.5% / 4.9% / 5.0%).

## 4. THE FINDING THAT SET THE DEFAULTS (sealed, pre-eval)

**The diagnosis's +0.184 / ×1.10 is an accounting artifact, and this build says
so before the arm runs.**

Replaying the mechanism *exactly as §5 P1 specifies it* — memo every repeat,
abort a batch on the first no-op **or revisit** — reproduces the published
multiplier (×1.1154 / ×1.1110 / ×1.0943) **and deletes the level-completing
action of three of the seventeen cleared levels on `animation_v1`.** The score
is then computed as if those levels were still cleared, which is where the
+0.184 comes from.

The mechanism is visible in the traces and is the same in all three cases: the
winning batch **opens by re-traversing already-visited boards** — the agent walks
back to a known position and then plays the winning move.

```
sp80 L1  step 62  batch 4/4   RIGHT(revisit) RIGHT(revisit) RIGHT(revisit) SPACE<-COMPLETES
tu93 L1  step  6  batch 16/16 DOWN(revisit)  RIGHT UP RIGHT ... DOWN<-COMPLETES
ar25 L1  step 23  batch 15/15 LEFT(revisit) x5  DOWN x9  DOWN<-COMPLETES
```

None of these actions no-ops; none closes an intra-batch loop. An
abort-on-revisit rule cuts every one of them at action 1. `tu93` and `ar25` are
also the two games the diagnosis names as supplying **87% of the entire claimed
gain**. `P1_MEMO_MODE=all` fails the same way for the same reason: the opening
`RIGHT`/`LEFT` actions are repeats of pairs executed before the RESET, so
declining them kills the same batches.

**Consequences, sealed:**
1. `P1_ABORT_REVISIT` ships **OFF** and `P1_MEMO_MODE` ships **`noop`**.
2. `P1_CONFIRM` is clamped to **≥ 2** in code: at confirm = 1 no pair is ever
   executed twice, so the latent-state detector can never fire and the hard
   safety constraint would be void. This is not a flag, it is a floor.
3. The honest expectation for what ships is **×1.02–1.04**, not ×1.10. **Any
   post-hoc reading of this arm against ×1.10 is out of order.**
4. The `memo_mode=all` and `abort_revisit=1` settings remain in the module as
   **ablation handles only**. Turning either on for a scored run requires a new
   prereg that addresses §4 head-on.

## 5. CANARIES (read from the build log; all pre-registered)

| id | requirement | source |
|---|---|---|
| **K-P0** | `p1 v1: ACTIVE (4 seams patched)` banner present, `applied=True`, `P1_SUPPRESS=1` stamped, **no** `PATCH FAILED` | cell 2 + cell 12 |
| **K-P1** | ≥ 1 `P1 ` event line on ≥ 5 distinct games | `P1 v=1 kind=…` |
| **K-P2** | the banner states `mode=noop`, `confirm=2`, `revisit is DEFAULT OFF` | cell 12 |
| **K-P3** | `errors=0` on the `P1 CANARY` line | canary |
| **K-P4** | `saved/requested` ∈ [3%, 30%] (M0) | canary |
| **K-P5** | the online detector flags ≥ 1 game (`ambiguous_games` non-empty) — the safety rule must be *live*, not merely present | canary |
| **K-P6** | `dup_rate` (M3) is **below** the family's as-run duplicate rate | canary |

K-P0..K-P3 are **hard**: any failure ⇒ the run is discard-grade and nothing may
be read from it. K-P4..K-P6 are **reading gates**: failure means the mechanism
did not deliver, and M1/M2 may not be read as evidence of anything.

**No token-fraction canary is pre-registered.** Mechanism C's cost is *input*
tokens; the rail reports **generated** tokens only (`final_uncached_input_tokens=0`),
so any token-fraction bound would be computed against a denominator that cannot
contain it. That is exactly the defect that killed the animation arm on a rule
that fired while the measured token effect was *negative*. The cost is instead
bounded **statically and verifiably**: the block is ≤ 900 characters by
construction, asserted by smoke check `U13` (measured 389 chars) and `I5c`.

## 6. KILL RULES (sealed)

The arm is **KILLED** — module reverted, nothing promoted, no submission, no
queue change — if any of:

1. **K-P0 or K-P3 fails** (patch did not install, or the action path raised).
2. **`levels_completed` ≤ 15** on the local 25 (as-run family sits at 10/16;
   the animation-composition run reached 17). *A drop to ≤ 15 is the diagnosis's
   own kill line and is retained verbatim.*
3. **Any game whose ambiguity flag fired loses a level** relative to the family
   per-game mean. The safety constraint is the point of the build; a violation
   kills it regardless of the aggregate.
4. **Any level-completing action is declined or aborted** — detectable post hoc
   because a declined/aborted action can never carry `level_completed`, so this
   is a *design* invariant, and its violation means the seams are wrong, not
   that the policy is wrong. Verified 0/0/0 in replay on all three runs.
5. **M0 < 3%** (mechanism did not engage) — the arm is a null by delivery and
   may not be re-read as a score result.

**Not a kill rule:** M2 below ×1.019. The replay expectation is a *point*
estimate on three runs of a stochastic agent; a single arm run cannot falsify it.

## 7. WHAT A PASS WOULD AND WOULD NOT LICENSE

**Would:** promoting P1 into the default eval composition, and unblocking P2
(verified-plan batch gating) and P3 (frontier-first exploration), both of which
assume a working transition record.

**Would not:** any claim that the efficiency lane reaches gold. The diagnosis's
own two independent ceiling estimators put the whole lane at ≈ 2.19 local ≈
1.26–1.36 LB, **short of the 1.48–1.58 gold line**, and this arm is the small,
certain part of that. On the shipped defaults its replayed effect is **+0.02 to
+0.07 local**, i.e. **≈ +0.01–0.04 LB** at c ≈ 0.58–0.62 — inside the noise of a
single draw (record s = 0.1513, n = 29). **This arm cannot be evaluated on one
LB draw and no LB draw may be attributed to it.**
