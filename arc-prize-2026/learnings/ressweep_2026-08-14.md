# FIELD 1 — LoRA / PEFT on agentic tasks, and the R-7 transfer risk

R-7 is "faster on solved games only, no transfer." I went looking specifically for a paper
that *measures* transfer of adapter training to an unseen task family. One exists, and it is
in-window.

## 1. CoAdapt-GUI — arXiv:2608.11588 (v1 **Aug 12, 2026**)
Guo, Gu, Jiang, Chi, Reid, Wang, Wang, Liu, Wang, Chen · `https://arxiv.org/abs/2608.11588`
**VERDICT: ADAPT — not as a mechanism, as the ablation design that prices R-7.**

Test-time adaptation for mobile GUI agents on **applications absent from source training**,
under a limited target interaction budget and **without target demonstrations** — structurally
the same setting as ours (private-LB games we have never seen, bounded action budget, no
labels). It jointly adapts (a) a **structured workflow context** that deliberately retains
transferable procedures, failure modes and verification rules while **excluding app-bound
source details**, and (b) a **LoRA adapter on a frozen VLM**, updated by task-context-matched
group-relative optimization on the agent's own target rollouts.

The number that matters to us is the ablation, not the headline:
**Policy-Only TTA = 37.5%; workflow-context + policy = 45.0%** on AndroidWorld-Generalization
(and 38.6% → 52.9% on AndroidWorld Plus). The authors' own reading is that
"transfer-constrained workflow context provides substantial gains and joint policy adaptation
**further** improves held-out performance."

**Read this the way it should be read: on unseen apps, the adapter is the smaller half.**
The larger half is a *non-parametric*, explicitly source-stripped text artifact. This is the
first quantified evidence I have found either way on R-7, and it points the same direction as
our own campaign history (`feedback_simplicity_wins`).

**What to take:** the *experimental contract*, not the method. If the LoRA lane is
pre-registered, it must carry a **Policy-Only arm** as a named cell, or the arm cannot
distinguish "the adapter transferred" from "the text artifact we bundled with it transferred."
Also take the **transfer-constraint rule**: whatever text artifact we carry across games must
be filtered to exclude game-bound specifics (sprite colours, coordinates, level names) — the
paper's central design claim is that this filtering is what makes the artifact transfer at all.
**Do not take** the GRPO policy loop: it needs reward-bearing rollouts and gradient steps on a
VLM, which we cannot buy under the zero-spend rule.
**Caveats:** base model sizes are not disclosed on the abs page (UNVERIFIED); GUI ≠ our
five-primitive action space; single paper, no replication.

## 2. MERA — arXiv:2608.10333 (v1 **Aug 11, 2026**)
Yao, Wang, Chen, Yang, Han, Xiao, Bao, Zhao, Ai, Yang, Shi · `https://arxiv.org/abs/2608.10333`
**VERDICT: IGNORE (needs a stronger teacher + GRPO; and its "held-out" is instances, not families).**

The closest match to our lane's *literal description*: replay **failed student invocations**
to get execution-verified **teacher** demonstrations, distil recurring procedures into an
iteratively-updated SkillBook, fine-tune a **student LoRA** by SFT + optional GRPO, admit a
candidate only when joint replay preserves task quality. Real numbers:
**Qwen2.5-Coder-1.5B 28.7% → 49.7%** on held-out HumanEval+MBPP over four cycles; deployed
policy retains **88.3% pass at 60.8% of always-teacher cost**; Qwen3.5-2B on TAU-2
**14/35 → 18/35**, matching an unadapted 4B.

Three disqualifiers, in order of severity. (a) The adaptation signal is **a stronger teacher
model**, which is exactly the cloud spend we do not have — this is distillation wearing
self-improvement's clothes. (b) **"Held-out" here means held-out coding problems, not a
held-out task family.** It therefore does *not* answer R-7; it is easy to mis-cite as if it
did. (c) 1.5B–2B students; nothing about a 27B FP8 or 122B NVFP4 base is exercised.
Worth logging that the *admission gate* — a candidate adapter is admitted only if joint replay
preserves quality — is the same shape as our own kill rules, and is the one part of the design
I would defend if the LoRA lane is ever built.

## 3. ExRole — arXiv:2608.11949 (v1 **Aug 12, 2026**) · `https://arxiv.org/abs/2608.11949`
**VERDICT: IGNORE (multi-hop QA, no interactive environment, no unseen-family test).**
Learns future-aware role prototypes from prefix-local team traces, resolves them into
instructions plus token-aligned role markers, and optionally routes **shared LoRA rank slots**
with turn-aligned credit. +15.0/14.4 and +13.5/16.1 EM/F1 on MuSiQue and 2WikiMultiHopQA over
single-agent search. It is a **multi-agent QA** result; we run one agent against a stateful
game. Model sizes not disclosed; generalization to unseen task families **not tested**.

## 4. MoRSE — arXiv:2608.09251 (v1 **Aug 10, 2026** — *just outside window*) · `https://arxiv.org/abs/2608.09251`
**VERDICT: IGNORE (the held-out claim is asserted with no number).**
Dynamic **Mixture of (role, subtask) LoRA Experts** over a shared LLM substrate with a
prototype-based semantic router, co-optimized with hierarchical GRPO and two-layer credit
assignment. Code-generation benchmarks, three backbones. The abstract states gains
"generalize across held-out task categories and domains" — **I could not retrieve a single
number attached to that claim.** An unquantified held-out claim is precisely what R-7 must not
be settled on. Also requires RL training we cannot buy.

## LoRA serving in vLLM over an NVFP4/FP4 base: **nothing new in this field.**
The date-sorted `LoRA × (FP4|NVFP4|quantized|vLLM)` query returned **zero in-window items** on
this intersection. The nearest prior art is all pre-window and all partial:
**PLoRA arXiv:2608.05483 (Aug 6)** is a near-data-processing *hardware* system;
**DeltaServe arXiv:2607.28848 (Jul 30)** converts idle vLLM inference capacity into LoRA
fine-tuning; **Agentic TTT arXiv:2607.03441 (Jul 3)** uses the vLLM runtime LoRA API for
in-episode adaptation. The live engineering question — **can vLLM serve a LoRA over an NVFP4
base where attention / shared-experts / lm_head are BF16 and only the MoE experts are FP4** —
is still not answered by any paper, and the FP8 case is still an **open vLLM RFC (issue
#33301, UNVERIFIED status)**. Treat this as an *engineering* unknown to be settled by a smoke
build, not by literature. It is a live risk to the lane independent of R-7.

# FIELD 2 — Action efficiency / step minimisation, executive rather than advisory

## 8. EpicStar — arXiv:2608.12626 (v1 **Aug 12, 2026**) — **top item of this sweep**
Wu, Hu · `https://arxiv.org/abs/2608.12626`
**VERDICT: ADAPT (the execute-gate only; strictly after the P1 arm is read).**

The only in-window item that is **executive rather than advisory**. Framing matches our
diagnosis almost word for word: "finite attention resources prevent the model from maintaining
strategic coherence over thousands of steps," producing *strategic drift*. The agent keeps a
**bank of successful past episodes** plus a **working memory** of short-term environmental
change, and at inference a **dynamic gate decides whether to execute a retrieved action
directly, or to reason anew** by fusing retrieved episodes with working memory. Testbed is
**StarCraft II** against diverse opponent styles; it beats baselines on win rate while
consuming **an order of magnitude fewer tokens**, consistently across difficulty levels.

Why this clears the bar the 08-12 sweep set and Memory-in-the-Loop did not: our problem is not
retrieval *latency* (`transitions` is already an in-process global) and not *advice* (that lane
is retired by RedundancyBench's 24.88%). It is that **every action costs a model call**, our
scorer is quadratic in wasted actions, and every game dies on the token budget. An execute-gate
is the first mechanism this campaign has seen that removes the model from the loop on the
actions it has already earned the right to skip.

**Concrete runner-side change (deterministic variant, zero LLM calls on the execute branch):**
on entering a `board_hash` already present in this game's own transition record on a path that
led to a level clear, **replay the recorded next action without a model call**; break out the
moment the observed transition diverges from the record. This is arithmetic over the memo P1
already maintains.
**Endpoint on our rail:** primary must be **delivery** — fraction of actions taken on the
replay branch, pre-registered with a band, same discipline as P1's M0. Secondaries:
tokens-per-cleared-level (our real binding constraint) and actions-per-cleared-level.
**Kill rule:** `levels_completed` on the local 25 must not fall; the 8 latent-state games
(m0r0, re86, sk48, ka59, cd82, g50t, dc22, wa30) must be **excluded from the replay branch
entirely** — replaying a recorded action in a game whose transitions are not a function of
`board_hash` is exactly the harm BeliefMem warned about.
**Load-bearing unknown (UNVERIFIED):** whether EpicStar's gate is itself a model call. If it
is, their token saving comes from shorter reasoning, not from skipped calls, and the paper
supports a weaker claim than the one above. **Our variant must use a deterministic gate
regardless**, so the mechanism does not depend on resolving this.
**Sequencing:** must not be built before `canivel/arc3-duck-p1-eval` v1 is pulled and read —
it modifies the same memo P1's block C is built on, and would confound the endpoint we are
already paying for. It is a **competitor** to the Prime-Agent pull-side helpers (08-12 item #1)
for the same successor slot, and on our evidence it is the stronger of the two, because it does
not depend on a 27B model choosing to call anything.

## 9. The LLM Proposes, the Executive Disposes — arXiv:2608.04066 (v1 **Aug 4, 2026** — *outside window, new to our record*)
Arjmandi (single author) · `https://arxiv.org/abs/2608.04066`
**VERDICT: IGNORE as a method — but this is the sweep's most important negative, and it is on our benchmark.**

This is the maximal form of the executive idea, run on **ARC-AGI-3**: a **deterministic
Executive owns all belief**; the LLM "may only file typed proposals"; a claim is admitted only
when a prediction **pre-registered before acting** is matched against observation **by code**.
Result: ablating the commitment mechanism flips goal-abandonment 0.00 → 1.00 while binding
error stays flat at 0.00, three seeds per cell, up to 394 reference beats per run.

**And the author discloses, pre-registered as a structural defeater, that task efficacy is
null: zero level completions across 52 gated runs on ARC-AGI-3.**

Read that number before anyone in this campaign proposes taking the executive framing further
than item #8's narrow replay gate. Taking the action fully out of the model's hands, on our
exact benchmark, has one published result and it is **zero**. Item #8 survives this because it
is a *bounded* executive — the model still chooses every action it has not already taken and
verified; the gate only skips re-derivation of actions the agent itself already earned.

Two secondary notes. (a) The instrument invalidates its own runs on per-organ write-error,
render-size and salted-canary-echo floors, and **four of the first eight architecture runs were
invalidated, each localizing a real defect.** That is independent, published support for
`feedback_audit_the_instrument` and for our preflight/canary discipline — the strongest such
support I have seen. (b) Single author, single instrument, self-reported; the ablation is
clean but the null efficacy means the instrument has never been validated against a
*succeeding* agent.

# FIELD 3 — Agent memory / state externalisation (ratified lane (a))

This field is **saturated and noisy**: the date-sorted query returned ~36 items in three days,
the overwhelming majority conversational (LoCoMo-family), multimodal-video, robotics, or
security. None of them is aimed at a stateful game agent that forgets its own transitions.

## 11. Beyond Retrieval / QCR — arXiv:2608.12847 (v1 **Aug 13, 2026**) · `https://arxiv.org/abs/2608.12847`
**VERDICT: IGNORE (spends LLM calls at reuse time; wrong benchmark family).**
Correctly identifies the gap left by every retrieval paper: retrieval says *which* past
trajectory matters, not *how to use it* once entities, constraints and environment state have
changed. Query-Conditioned Reuse encodes procedures, variable bindings, applicability
conditions and verification steps. **62.3% average success, +10.7 pts over a Full-Trajectory
baseline, 48.9% fewer online tokens**, 2,391 target instances across WebArena / WorkArena /
AppWorld; summary reranking reaches 94.8% coverage, within 1.8 pts of an oracle selector.
The 48.9% token cut is real currency for us — but **QCR requires LLM calls at reuse time to
adapt the retrieved trajectory**, and our binding constraint is the token budget itself.
Paying model calls to save model calls is a trade we cannot price, the same objection that
killed *Less Context* (08-12 item #5). Applicability conditions are a good idea we already get
for free from `board_hash` equality under determinism.

## 12. The Sleeping Agent — arXiv:2608.11775 (v1 **Aug 12, 2026**) · `https://arxiv.org/abs/2608.11775`
**VERDICT: IGNORE as a method — keep one sentence of it as a design warning.**
Uses Salience-Weighted Consolidation as a diagnostic probe on all ten LoCoMo conversations
(1,935 matched questions, 1,501 in the primary aggregate, temperature 0). Finding: gist
compression **beats truncation** on multi-hop and single-hop factual questions but is
**substantially worse on temporal questions**, and the mechanism is identified precisely — the
gist prompt "preserves relational and event structure while **discarding dates and times**."
A one-sentence prompt change raises temporal-expression preservation **3.05% → 62.39% (~20×)**
while entity and event preservation barely move (×1.02, ×1.11), recovering **+0.314
[0.254, 0.375]** judge accuracy on temporal questions.

IGNORE as a method: it is a prompt fix on a conversational benchmark, single author, and
`feedback_prompt_is_noise` applies. **Keep the warning**, which is cheap and testable:
*summarisation preserves structure and destroys order.* Our P1 block C is a deterministic
summary. If it reports **what** was tried without preserving **when** / in what order, this
paper says that is the axis on which it will silently fail. Worth one grep of block C's
renderer for ordering information when P1 is read — free, no build.

## 13. When Your Agent Opens the Chat App — arXiv:2608.12888 (Aug 13) · `https://arxiv.org/abs/2608.12888`
**VERDICT: IGNORE — logged as a useful negative.**
Finds **unstructured lexical search rivals graph-based memory systems** for conversational
agent retrieval. Second published warning this month (after RedundancyBench) that elaborate
memory machinery does not beat the dumb baseline. Nothing to build; use it to resist the next
graph-memory proposal.

# FIELD 5 — Large MoE inference economics

## 16. **Nothing new in this field** — but the decisive paper already exists and is not on our record.
The date-sorted MoE×inference/serving query returned five in-window items and **not one bears
on per-token bandwidth or MoE-vs-dense batch-scaling economics**: `2608.12103` (Aug 12, OS page
cache vs user-space expert cache for trillion-parameter serving), `2608.11688` APEX (Aug 12,
edge expert prefetching, −26% latency), `2608.11668` HBF (Aug 12/13, high-bandwidth flash for
KV offload), `2608.10392` UniF-MoE (Aug 11, shared-experts-plus-routing architecture),
`2608.10614` (Aug 11, router-poisoning straggler attack). All are cluster/edge infrastructure,
irrelevant to a single-GPU Kaggle build kernel.

**The item that actually prices our 122B NVFP4 decision is four months old and, as far as I can
tell, has never been on the campaign record: the *qs* Inequality — arXiv:2603.08960 (Mar 9,
2026), "Quantifying the Double Penalty of Mixture-of-Experts at Inference."**
`https://arxiv.org/abs/2603.08960` · **VERDICT: IGNORE as new — flagged as required reading.**

It formalises a **double penalty** for MoE at decode: (a) expert routing **fragments
microbatches and destroys weight reuse**, so the effective bytes-per-useful-token is far worse
than the activated-parameter count suggests; (b) the **resident expert pool eats HBM headroom
for the KV cache**, pushing FFNs into a bandwidth-bound regime *especially at long context*.
The *qs* inequality predicts when MoE is structurally disadvantaged versus a **quality-matched
dense** model, unifying sparsity `s` (fraction of parameters activated per token) with a
quality-equivalence factor `q` (the size multiplier a dense model needs to match). Evaluated
across DeepSeek-V3, Qwen3-235B, Grok-1, Switch-C; for **DeepSeek-V3 at 128k context it reports
a 4.5× throughput advantage for the quality-matched dense baseline.**

Why this matters right now, and why it is being flagged rather than filed: our own census just
corrected the 122B NVFP4 candidate from a claimed 5× to a measured **~1.5×** lighter than the
27B-FP8 incumbent (~17–18 GB/token, because only the MoE experts are FP4 while attention,
shared experts and lm_head stay BF16). **The *qs* paper says the remaining 1.5× is itself an
optimistic ceiling**, because it is a static bytes-per-token figure that ignores reuse
fragmentation and KV-headroom loss — and **both penalties scale with context length**, on a
workload where our games already die at 66–69k tokens. The census number and this paper point
the same way and the honest conclusion is that **the 122B brain's remaining margin over the
incumbent is thinner than 1.5×, possibly inverted at our context lengths.** That is a claim we
can test cheaply on the build rail (measure decode throughput at 8k vs 64k context on both
candidates) *before* any further slots are spent on the swap. No new paper is needed to justify
that measurement; this one just says it should be pre-registered as a **kill** condition, not a
sanity check.

# Net

**Zero ADOPTs — correct outcome, fourth sweep running.** Nothing in a three-day window is both
new and buildable by 2026-11-02 on free compute.

**The two ADAPTs are asymmetric and should be treated differently.**

**#8 EpicStar is the sweep's find**, and it is the first *executive* mechanism this campaign has
seen: a gate that executes a retrieved action **instead of** calling the model. It is the only
proposal in three sweeps that attacks our actual binding constraint — the token budget, not
the action count — and its deterministic variant costs nothing at inference. It competes with
the Prime-Agent pull-side helpers for the successor slot after P1, and it is stronger, because
it **does not require a 27B model to choose to do anything**, which is the exact failure that
put us here. It must not be built before the P1 arm is read.

**#1 CoAdapt-GUI is not a mechanism, it is a verdict on our lane.** On unseen apps, **Policy-Only
TTA scores 37.5% against 45.0% for context+policy** — the adapter is the *smaller* half of
transfer, and the larger half is a source-stripped text artifact requiring no gradients. R-7 is
not refuted, and this is the first quantified evidence that it is real. If the LoRA lane is
pre-registered, a **Policy-Only cell is mandatory**, or the arm cannot tell which half worked.
**RMSWeb's "19.7% fewer steps on solved tasks" (2608.00335, Jul 31) is R-7's exact shape
observed independently in web agents** — cite it whenever the lane's efficiency story is priced.

**The most important number in this document is a zero.** arXiv:2608.04066 built the maximal
deterministic-executive agent — the LLM may only file typed proposals, code owns all belief —
ran it on **ARC-AGI-3**, and reports **zero level completions across 52 gated runs**, disclosed
under pre-registration as a structural defeater. Whatever we take from #8 must stay bounded:
skip re-derivation of what the agent already earned, never take the choosing away.

**Two field-level nulls worth recording.** (a) **No ARC-AGI-3 paper exists in the window** —
the whole literature is 16 papers and the newest is Aug 4. (b) **No paper anywhere addresses
LoRA over an NVFP4 base with mixed-precision attention in vLLM**; that is an engineering
unknown to be settled by a smoke build, and it is a live risk to the lane orthogonal to R-7.

**One overdue read.** The *qs* Inequality (2603.08960) should have been on our record before
the 122B census, not after. It says the corrected 1.5× advantage is an optimistic static
ceiling that reuse fragmentation and KV-headroom loss erode **as context grows** — on a
workload dying at 66–69k tokens. Pre-register a throughput-at-64k-context kill condition before
another slot is spent on the swap.

**Standing pattern from Field 4, offered as the sweep's one strategic observation:** every
published ARC-AGI-3 *win* (Tycho, OPINE-World, Executable World Models, Prime Agent) comes from
an agent that writes and maintains **executable code models** of the game; every published
*null* (2608.04066) and every weak result (AERA, 0.5B) comes from an agent that reasons in
text. We cannot buy a frontier coding agent — but our harness already hands the agent a live
Python tool, and that is the cheapest unexploited alignment with this pattern we have.
